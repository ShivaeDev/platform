# @shivaedev/agent

Applications declare what they need from a coding agent here. A configured backend supplies a run port and explicit feature implementations; the application negotiates a typed facade before any provider work. The vocabulary comes from Claude Code, Codex, OpenCode and Pi. Provider adapters belong in their own packages.

Truth about acceptance wins over convenience: an acknowledgement is not completion, missing evidence is not failure, and uncertainty never authorises replacement work. Keep steering distinct from queued input, and absent accounting distinct from zero. Prefer Schema data and native Effect lifecycle semantics over wrappers. This package owns no journal, storage, provider SDK or runtime process.

Read the [README](README.md) for the public contract and the repository [AGENTS.md](../../AGENTS.md) for development conventions. The story kit exercises negotiation and dispatch against a scripted provider boundary; it must keep the real facade running and expose outbound calls, not assert its own script as product behavior.
