# @shivaedev/work-fleet

You are changing Work Fleet, the optional execution addon to Work Board. A maintainer approves Board work; Fleet carries independent items through workers, independent review, scoped repair, required validation and observed human delivery, so the person sees only work that is active, completed or waiting on one concrete decision. The hard part is not launching agents but staying correct while providers drop replies, turns go missing, daemons restart and people edit briefs mid-run. Read [the README](README.md) for usage and [docs/](docs/) for the execution protocol, worker markers and follower streams.

The ideal is a fleet a person can trust without watching it. Board owns identity, context, relationships and human decisions, and stays useful without Fleet; its index and PubSub are rebuildable observations, not an attempts database. Fleet attaches durable execution and accepted outcomes to those Board IDs in ordinary transactional SQL, with no separate task queue, daemon-wide decision lock or event journal. A headless runtime still reads Board core, and the browser is optional.

## Which way to lean

When goals conflict, they win in this order:

1. **Authority stays with people and runtime policy.** Fleet never submits a merge; reviewed, green work waits for a human merge, which reconciliation adopts against the reviewed head. Runtime policy owns authority and the provider, source observation, review, validation and delivery integrations. Worker output and answer text cannot grant authority, and Fleet never bypasses protections.
2. **No execution is lost or duplicated.** Submission intent precedes remote mutation, and acknowledged session and turn identities are saved before further mutation. Ambiguous acceptance keeps its reservation: preserve uncertain ownership and reconcile the existing operation instead of starting another. Closing observation does not interrupt execution; explicit interruption needs acknowledgement. Terminal execution releases capacity, but ownership ends only at accepted delivery, reviewed and validated no-change, or explicit safe release.
3. **Native Effect, one path per job.** Scope, interruption, typed failures and transactions carry these guarantees; do not rebuild them beside Effect. Keep the session service, which handles one provider conversation and its turns, independent of scheduling, dependencies and merge authority. Board stays the one owner of the work's identity and human decisions.
4. **Evidence is exact and claims stay within it.** A provider receipt, a terminal turn, a passing review and an accepted delivery are distinct facts. Review and checks apply to an exact revision, and repair needs fresh evidence. Read only explicit markers, never inferred prose. A local Codex transport or a synthetic server proves nothing about hosted Cloud or live GitHub.
5. **Each wait asks one concrete question of one owner.** Every wait names the maintainer, the orchestrator or automation and the reason. Recover routine faults automatically and stay quiet; escalate only what Fleet cannot settle safely, with options that can actually help.
6. **Throughput comes last.** Merge throughput, not launch throughput, limits a fleet. Pace, retry and parallelize freely within the rules above, never at their expense.
