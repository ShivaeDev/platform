# Reading the Board

This guide describes each page of the Board, organized by what the reader does on it. The [README](../README.md) explains how to think about a Board, how to author its files and how to integrate with it.

## Start from Today

The first screen at `/` is **Today**: a linked summary, **Needs you**, **Answered**, **In progress**, **Later** and **Goals**. Human asks come from the shared attention projection. Answer opens a popover that records an answer against the current reviewed context: buttons for a one-choice question, or a text box for a text question or a request without questions. In progress shows up to eight items Fleet holds in working or reviewing, each marked **Fleet** with its recorded PR link; **All in Now →** opens the full work view. Its summary counts all held items, including those beyond the preview. When the Fleet daemon is not running, In progress says so in one sentence and keeps the start command behind **How to start Fleet**. When Fleet is unavailable, In progress falls back to the task files the same way Now does: it lists ready tasks, shows the status written in each, says the status comes from each task and not from Fleet, and the summary reads **N marked in progress**. The count stays unknown until the files are read. Goal cards show the next action clamped to two lines and five colored task segments with an **N/M done** count; criteria and their evidence counts sit behind a closed **Criteria** disclosure. These counts describe recorded source, not verified success. **Later** lists parked work with its count, closed by default: deferred items that would otherwise need you, each showing its `next_action`. It appears only when such items exist. The breadcrumb root **Workspace** opens Today. An empty Today links to getting-started guidance only while the workspace has no identified documents.

## Find your way

The sidebar shows Today, Goals, Now, Library and System, with counts only on Today and Now, followed by pinned documents, active goals with linked-work status bars and quiet done/total figures, and at most five recent documents, leaving out pinned documents and the open page. Active goals are left out while Today is open, since Today lists them itself. Today counts waiting human actions and Now counts open tasks. Each active-goal bar names its done count for assistive technology and shows the same count on hover. The top bar's Sidebar button hides or shows the sidebar, and its Today link appears while the sidebar is hidden. Below 768px, Sidebar opens an overlay drawer; Escape or a tap outside closes it and returns focus to Sidebar, and the phone navigation's More sheet holds Library, System, pinned and recent documents and reading history. The phone navigation's Today tab carries the same needs-you count as the sidebar, as a badge when it is above zero. The sidebar, top bar and phone tab share one needs-you badge, in the needs-you colour when the count is above zero. At zero none of them shows a badge; the sidebar and top bar keep the count for screen readers. Library opens on Recently changed, newest file first, and can also list documents by title or by folder, where a folder loads its immediate children on expansion. **Find documents** keeps the documents whose title or ID contains every typed word, as Now's **Find work** does, and Kind and Status filters narrow the list further. The text, kind, status, view and **Include files Fleet writes** choice live in the URL, so Back, reload and a shared link reopen the same list. The list renders 100 rows and says how many documents match in all; **Show more** adds the next 100 and moves focus to the first new row, and Back from a document returns to the same rows. Links preserve logical workspace paths, including reference-directory aliases.

Back restores selected text and expanded details. Reading history opens a dialog with pinned documents and the last 30 unique documents read, grouped by day. Each entry shows when it was read, its kind and its status; **Remove** drops one entry and **Clear history** drops them all after an in-page confirmation, keeping pinned documents. Pinned and recent documents belong to the workspace/origin; deleted documents remain labeled missing. Save up to ten named Work views with the applied board, filters, sort and layout. Selection stays in the URL, and saving the same name updates it. At capacity, remove or update a view; none is silently evicted. Unavailable storage is disclosed, with controls usable for the current page.

Every time on the Board reads the same way, in the browser's locale: `just now` under a minute, relative under a week, such as `4m ago` or `in 2h`, and a short date after, such as `Oct 13, 09:35`, with the year only when it differs. Where a time is the content itself, on the Source tab records, System and the document context panel, point at, tap or focus and activate it to see its exact date, time and time zone. In list rows on Today, Now, Library and response history a time is plain text that adds no Tab stop, and pointing at it shows the exact time.

## Search the workspace

**Search** or Ctrl/Cmd+K opens the command palette. Go-to commands open Today, Goals, Now, Library, System and each open goal from the goals query. Appearance commands toggle the file sidebar, density and theme. Results update as you type, and Enter in the field searches an unfinished query at once. With an empty query, a **Needs you** group above the commands lists the items Today shows as needing you, so Enter opens the first one. Rows sit under **Needs you**, **Go to**, **Appearance**, **Work** and **Documents** headings. With an empty query the groups keep that order. While searching, a row whose title or ID matches the query exactly comes first, whatever its group, then a row whose title or ID starts with a query of two or more words; the other groups follow their best row (title match before body match), and ties keep the order above. Search finds document titles/paths, IDs, headings, passages and recorded work fields. Matching uses the first 200 query characters and up to eight terms; each term must occur in a block, ignoring case. Exact and starts-with title or ID matches rank first, before the result limit, and an ID also matches by its last segment, so `answer card` finds `board.answer-card`. Other item results rank before headings and passages. Within items, other title and ID matches follow, then body matches; within each, open work ranks before closed and deferred work, then the most recently changed sources come first. Body matches also return the item itself. A document's title and the passages under it share the document's own row. Each anchor appears once, retaining its best match before the result limit and count. Rows show their kind; item results also show their ID and authored status; rows without a recorded status omit the chip. Fleet decisions, captured questions, responses, application receipts, `fleet/status.md` and `responses/fleet-report.*` appear only while **Include files Fleet writes** is checked or when the query starts with `records:`. Snippets show inline Markdown as plain text, mark the searched words, omit structured metadata and never repeat the row's title; a row whose title matched shows the next matching passage under the same anchor, or no snippet. At most 40 source results are shown with the full match count, and a list cut short asks for more words or an ID. Arrow keys choose, Enter opens, and Escape closes. Incomplete reads are disclosed, a failed search offers **Retry search**, and older requests cannot replace a newer query. Search requires JavaScript.

## Read an item

Identified documents open with a sticky title, kind icon, recorded status, owner and next action. While the reader scrolls, the sticky header shrinks to a one-line title. Pin and handoff controls sit in the header. Known Fleet items also show their stage and PR. Open questions and attention requests in other files that name the item, through a relationship or `unblocks`, lead the header: **Waiting on you** in amber with an **Answer** link to the ask's answer card when it waits on you, and **Waiting on automation** in neutral colours when only agents can answer it. Below 768px a question page shows an **Answer** button at the top that moves to its answer card and focuses the answer box. In the next action, an item ID or workspace path that names one document shows that document's title as a link with its status chip; other words stay plain. `#123`, `PR #123` and `PR 123` link to that pull request when the nearest `package.json` above the workspace names a GitHub `repository`, or the enclosing git checkout's `origin` remote is on GitHub; otherwise they link only while every Fleet pull request is in one repository. Criteria render inline Markdown. An open rail shows up to three short criteria, relationships with target titles and statuses, and backlinks grouped by kind; membership and Markdown links keep their own groups. Longer criteria lists follow the body in the main column. On wide screens the rail sits beside the Markdown column, with an **On this page** outline below it that stays in view while the reader scrolls and marks the section being read; on smaller screens the rail follows the introduction and an **On this page** button in the header opens the outline. The Source tab holds the file location, original frontmatter and recorded handoff, question, response and request-receipt details. Passage links into Source reveal the tab before scrolling and focusing the record.

## Answer on the item page

Open requests place an answer card directly below their source header and the headers of the items they unblock. A standalone question places its card after its own text, so its context reads before the answer box. The card renders the reason as Markdown, offers the recorded options with the recommendation marked, and retains response drafts through live reads. The answer box grows with the answer up to most of the screen height. Following a link to an answer card puts focus on the first option of a choice question, or in the answer box. Record saves the answer against the request’s reviewed source under the author label the browser remembers, or maintainer when no label is saved; the card does not show the label. **More options** holds the kind of reply, a choice to replace an earlier answer when one exists, Markdown preview and draft tools. When a question closes while you write, its card stays with your unsent draft read-only, a **Copy draft** button and what closed it. Managed decisions use the title of the work they unblock; generated identities remain in Source.

## Read a goal

A `kind: goal` page puts goal progress before its authored Markdown: a five-segment progress bar, the goals query's progress counts written out, and a stacked bar chart of those states for all linked work and for each criterion with linked work. Zero counts render as muted labels. The segments are green for done, yellow-orange for running, red for blocked, blue for scheduled and gray for parked, with state names on hover. Open asks show as an amber link to the answer card, or, when there are several, as an amber control that opens a list of links to each answer card; with no open asks nothing is shown. A goal with no linked work shows an empty state instead of the progress bar, counts and the linked work section. The progress header sits immediately below the item header, before open answer cards. Criteria, linked work and prose follow the answer cards. Each criterion is a card with its text, a one-line count summary and its linked items in a disclosure, closed by default. Linked work below the criteria is a table per state group, grouped by authored status: Ready is open; Draft, Deferred, Dropped and Done are closed disclosures whose rows stay findable in the page. Tables have Work, Criteria, State and PR columns, and Ready adds Owner and Updated, the later of the file change and the Fleet update. Each whole row links to its item. These are work counts, never an overall success state or percentage. The open asks use the same eligible, active, grouped rows as the maintainer's Today attention list; resolved, parked and earlier grouped asks do not add to them.

Each criterion shows its progress split in one small line, targeting items and recorded evidence when present. Untargeted criteria retain their text without an extra label; absent evidence stays quiet. Each row and criterion link has one state chip: the Fleet stage while held, otherwise the authored status. A released stage falls back to authored status; missing status and missing PR leave blank cells. Items without status belong to Draft. The outline rail remains beside the prose on wide screens and follows it on narrow screens. Closed projects show the same goal and criterion counts as open projects while staying outside active-goal navigation.

## Follow live changes

**Pause updates** holds the displayed reading state while counting observed hints, bounded at **256+**. Resume and reconnect reconcile the workspace. Unrelated source edits retain mounted document reads; relevant updates retain unchanged reading blocks. A failed read keeps visible source and says **refresh failed**. Before the first live update, and while the source watcher has not yet answered, it says **connecting**. A page starts its reads after that first update, so opening it reads each piece of data once; a failed connection does not hold the page. A file event that changes neither the bytes nor the modification time sends no update; a new modification time alone does. Connection or watcher loss says **reconnecting**. Below 768px the header shows only these problems, paused updates, a failed refresh or reconnecting, as an icon and a short word in a polite status region, and stays empty otherwise. These are reconciliation hints, not a durable event journal or a count of completed work.
