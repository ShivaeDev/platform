# @shivaedev/work-board-plugin

The Work Board plugin brings the running Work Board into Claude Code, so a session sees what needs the maintainer, what Fleet has in flight and how goals are progressing without leaving the prompt. It is a Claude Code mod: a hooks module the Claude Code engine loads and draws, shipped from this repository's plugin marketplace and never published to npm.

The Board stays the source of truth. The plugin only reads it. It discovers the browser address over the `board.sock` of the nearest `.work` folder at or above the session's folder, then follows authorized contract queries and runs tools over one Platform WebSocket. It answers with what the Board said or why it could not ask: no Board in this folder, a Board that is not running, or a request it refused. It never writes to the Board and never guesses state it was not given.

When goals conflict, a truthful view comes first, then one quiet glance (a single band line, a toast only for a new decision), then parity with the Board's own MCP tools, then visual polish.

The engine sets the rules this package lives by: JSX against its global `h`, the `claude-code` module it provides at runtime, and relative imports in the generated hook it loads. The package never installs or runs Claude Code. `src/claude-code.d.ts` hand-declares only the part of that module the plugin uses, shaped from what the code calls, so the whole package typechecks with nothing downloaded; when the plugin starts using more of the API, or the API changes, update that file by hand. The authored code lives in `src/` and uses the package's aliases. `pnpm build:client` bundles the native Effect client and hooks into an ignored generated directory; `hooks/hooks.json` loads that generated hook entry. Checkout setup, builds and test preparation generate it. The marketplace command source builds from a fresh repository checkout and gives Claude Code a self-contained plugin directory.

Pane stories feed Board replies through the plugin's parsers and render its element port with React in happy-dom. They prove the pane's text, counts and supplied colors; they do not run Claude Code, so the runtime hooks, band and toasts are checked by loading the plugin into Claude Code with `--plugin-dir`. The contract spec in `@shivaedev/work-board` (`src/rpc/claudePluginContract.spec.ts`) feeds a real Board's answers through the plugin's parsers, so a Board reply change that breaks the plugin fails there. Keep parsing and shaping in modules that import no `claude-code` value so CI covers them. Usage and install live in the [README](README.md); the Board's queries live in [`@shivaedev/work-board`](../work-board/README.md).
