### Added

- `@shivaedev/quality`: `effect/adapter-bridges` reports each production module in an `adapters/` folder that uses nothing Quality forbids elsewhere, so `adapters/` holds only code that needs it. A module stays when `effect/boundary` in either half, `effect/adapter-imports`, `effect/context-capture`, `effect/unsafe-calls`, the hidden-cast checks of `suppressions/no-double-cast` or the runtime and browser I/O bans of the `ambient-runtime` Biome plugin would report it outside `adapters/`; a service folder stays whole while any of its modules does. Those rules now also read `adapters/` and the engine keeps what they find there as evidence instead of reporting it. The rule runs in CI and with `quality lint --full`. To adopt it, update imports of the moved Platform modules below, run `quality lint --full`, and move each reported `adapters/` module of the application out of `adapters/`, usually to the parent folder, or record the findings with `quality baseline write --rule effect/adapter-bridges`.
- `@shivaedev/quality`: a `Finding` may set `unsafe: true` when it reports something `adapters/` permits; the engine then drops it in `adapters/` and `test-support/` and counts it as evidence for `effect/adapter-bridges`.
